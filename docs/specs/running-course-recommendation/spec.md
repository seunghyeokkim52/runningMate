# 지도 기반 순환 러닝 코스 추천

`PRODUCT.md`의 핵심 루프("거리 입력 → 현재 위치 기반 순환 코스 여러 후보 추천 → 선택 → 완주 → 개인 로그")를 구현 가능한 계약으로 정리한다.

## User-visible outcomes

- 로그인한 사용자가 원하는 거리(km)를 입력하면, 현재 위치에서 출발해 같은 지점으로 되돌아오는 순환 러닝 코스 후보를 지도 위에서 여러 개 확인할 수 있다.
- 각 후보는 실제로 뛰기 좋은 길(보도·공원길 우선, 차량 통행이 많은 도로·급경사 회피)로 계산된 경로다.
- 사용자는 후보 중 하나를 선택해 지도에서 강조된 경로를 확인하고, 뛴 뒤 완주를 표시하면 그 기록(거리·날짜)이 내 로그에 남는다.
- 현재 위치가 대한민국 밖이거나 위치를 가져올 수 없어도, 대한민국 내 주소를 직접 입력해 출발 지점으로 지정할 수 있다. 이렇게 지정한 지점을 기준으로도 동일하게 순환 코스를 추천받을 수 있다.
- 출발 지점으로 확정된 지점(현재 위치든 입력한 주소든)이 대한민국 밖이면 코스 대신 이용 불가 안내를 본다.

## Approved scope

- 거리 입력 UI, 출발 지점 확보(현재 위치 GPS 획득 또는 주소 검색·지오코딩), 순환 코스 후보 계산·추천, 지도에 후보/선택 경로 표시.
- 완주를 수동으로 표시하는 동작과 그 결과를 개인 로그로 저장하는 동작.
- 확정된 출발 지점이 대한민국 경계 밖일 때의 이용 불가 안내.

## Observable acceptance criteria

- 로그인한 사용자가 대한민국 내 현재 위치에서 거리를 입력하면, 그 위치에서 출발·복귀하는 순환 코스 후보가 3개 지도와 함께 표시된다.
- 현재 위치가 대한민국 밖이거나 위치를 가져올 수 없는 사용자는 주소를 입력해 출발 지점을 지정할 수 있고, 입력한 주소가 대한민국 내로 확인되면 그 지점을 기준으로 동일하게 코스 후보 3개가 표시된다.
- 입력한 주소가 지오코딩되지 않거나 대한민국 밖으로 확인되면, 코스 후보 대신 "대한민국 내 주소를 입력해 주세요" 안내가 표시된다.
- 각 후보 경로의 실제 거리는 입력한 거리의 ±10% 이내다.
- 각 후보 경로는 Valhalla pedestrian costing(`walkway_factor`/`sidewalk_factor`로 보도·공원길 우선, `use_hills`로 경사 회피, `alley_factor`로 좁은 길 회피) 기준으로 계산된 결과다.
- 사용자가 후보 하나를 선택하면 해당 경로만 지도에 강조 표시된다.
- 사용자가 완주를 표시하면 계정에 거리·날짜가 포함된 기록이 남고, 사용자는 자신의 과거 기록 목록을 볼 수 있다.
- 로그인하지 않은 사용자는 코스 추천 화면에 접근할 수 없다.
- 확정된 출발 지점(현재 위치 또는 입력한 주소)이 대한민국 경계 밖이면 코스 후보 대신 "대한민국 내에서만 이용 가능" 안내가 표시되고, 거리 입력은 비활성화된다.
- 요청 반경 안에서 유효한 순환 코스를 만들 수 없으면(예: 도로망이 희박한 지역), 오류 없이 "이 위치·거리로는 추천할 수 있는 코스가 없다"는 상태를 보여준다.

## Settled constraints and rationale

- 지역 범위는 대한민국 전체다 (`PRODUCT.md`).
- 다양성은 사용자별 이력을 기억해 자동으로 회피하는 방식이 아니라, 매번 여러 후보를 제시하고 사용자가 고르는 방식으로 만든다 (`PRODUCT.md`). 즉 추천 알고리즘 자체는 사용자의 과거 기록으로 개인화되지 않는다.
- 계정 가입이 필요하다. 계정에 남는 기록은 사용자 개인의 완주 로그 용도이며 추천 로직에 반영되지 않는다 (`PRODUCT.md`).
- 순환 코스 계산과 지도 표시에 쓰는 구체적인 기술과 그 근거는 [course-routing 결정](../../decisions/course-routing.md)을 따른다: 라우팅 엔진은 자체 호스팅 Valhalla, 지도 시각화는 Kakao Maps JavaScript SDK, 주소 지오코딩은 같은 SDK의 `services.Geocoder`.
- 일반 UI(거리 입력, 후보 목록, 상태 표시)의 구성 방식은 [ui-composition 결정](../../decisions/ui-composition.md)을 따른다. 지도 자체는 이 결정이 이미 예외로 인정한 custom UI 표면이다.

## Assumptions

- 후보 코스 개수는 3개로 시작하고, 실사용 튜닝에 따라 조정할 수 있다.
- 거리 허용 오차는 입력 거리의 ±10%로 시작하고, 조정할 수 있다.
- 완주 여부는 사용자가 직접 "완주" 조작으로 표시하며, 실행 중 실시간 GPS로 진행률을 자동 추적하지 않는다.
- 위치 권한이 거부되거나 위치를 가져올 수 없을 때는 코스를 추천하지 않고 위치 권한이 필요하다는 안내를 보여준다.
- 지역별 OpenStreetMap 보행로 데이터 밀도 차이로 코스 품질이 균일하지 않을 수 있다는 점은 감수한다(Remaining risks 참고).

## Off-limits areas and why

- 실시간 GPS 추적 기반 자동 완주 감지, 페이스·심박 등 러닝 중 지표 측정은 범위 밖이다. `PRODUCT.md`의 약속은 "선택해서 완주한다"까지이며, 실행 중 트래킹은 별도로 다룰 만큼 크고 독립적인 기능이다.
- 계정/로그인 시스템 자체의 구현 방식(가입 절차, 인증 수단)은 범위 밖이다. 이 스펙은 "로그인이 필요하다"는 제약만 전제한다.
- 대한민국 외 지역 지원은 범위 밖이다.
- 과거 기록 기반 추천 개인화는 범위 밖이다. `PRODUCT.md`가 이미 배제했다.

## Deferred points

- 경사 회피(`use_hills`)를 온전히 활성화하려면 Valhalla 그래프 빌드 시 별도의 고도(DEM) 데이터가 필요할 수 있다. 확보 방식은 구현 단계에서 정한다. 확보 전까지는 보도·공원 우선(`walkway_factor`/`sidewalk_factor`)만으로 코스를 계산하는 것을 interim 동작으로 둔다.
- 완주 자동 감지(실시간 GPS 트래킹) 도입 여부는 이후 별도 작업으로 결정한다.

## Remaining risks

- OpenStreetMap의 보행로 데이터는 커뮤니티 편집 데이터라 지역마다 실제 도로 상황과 다르거나 일부 구간이 누락될 수 있어, 특정 위치·거리(특히 도로망이 성긴 농촌·산간 지역)에서는 후보 코스 품질이 낮거나 아예 생성되지 않을 수 있다.
- Valhalla 자체 호스팅에 필요한 서버 인프라와 운영 부담이 새로 생긴다.
- Kakao Maps JavaScript SDK는 도메인당 API 키 등록이 필요하고 무료 사용량에 한도가 있어, 트래픽이 늘면 비용이 발생할 수 있다.
